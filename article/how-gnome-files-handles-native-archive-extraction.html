How GNOME Files Handles Native Archive Extraction

GNOME Files, formerly and often known as Nautilus, provides a streamlined experience for handling compressed files directly within its active directory view. Rather than relying on external archive manager windows, modern GNOME Files manages archive extraction in place using built-in backend libraries, asynchronous execution, and automated safety logic. This native integration ensures that compressed contents are unpacked smoothly into the current parent directory while automatically preventing clutter and keeping the user interface fully responsive.

Backend Integration with libarchive

GNOME Files relies directly on the libarchive library to read, decompress, and write archive contents. Previously, the desktop environment delegated decompression tasks to external graphical utilities such as File Roller. By integrating libarchive directly into the file manager’s runtime operations, GNOME Files treats extraction as a native file system operation similar to copying or moving files. This backend supports a wide range of common compression formats, including .tar.gz, .tar.xz, .zip, and .7z, handling format parsing and decompression internally without spawning external process windows.

Smart Extraction and Directory Detection

When a user initiates an extraction within a parent folder, GNOME Files scans the internal structure of the archive before writing files to the disk. This mechanism, known as "smart extraction," prevents the directory view from becoming cluttered with loose files:

  • Single-Root Archives: If the archive already contains all its files within a single top-level folder, GNOME Files extracts that folder directly into the parent listing.
  • Multi-Item Archives (Tarbombs): If the archive contains multiple loose files and folders at the root level, GNOME Files automatically creates a new directory named after the archive and places the unpacked contents inside it.

This dynamic check ensures that unpacking an archive containing hundreds of loose files does not disrupt the parent directory layout.

Asynchronous Operations and View Updates

Decompressing files can consume significant system resources and time depending on the file size. GNOME Files executes extraction tasks asynchronously through GLib’s GTask infrastructure and the GNOME Virtual File System (GVfs).

Because decompression runs in separate worker threads, the main graphical interface remains interactive. Progress is reported via an operational popover in the window's top bar rather than blocking modal dialogs.

As files are extracted, GVfs file monitors continuously notify the file listing model of newly created nodes. The view model updates its list or grid view instantly, displaying extracted folders and items in real time without requiring the user to manually reload or refresh the current folder.

Integrated Action History and Undo Support

Because extraction operations are integrated directly into the file manager's native transaction pipeline, they hook into the universal undo system. GNOME Files registers the newly created files and directories as an atomic operation. If an archive is extracted accidentally, pressing the standard undo shortcut (Ctrl+Z) prompts the file manager to reverse the operation by deleting the extracted contents from the parent listing in a single step.
