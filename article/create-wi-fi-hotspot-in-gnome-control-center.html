Create Wi-Fi Hotspot in GNOME Control Center

This article explains how the GNOME desktop environment handles Wi-Fi hotspot creation and internet connection sharing using the GNOME Control Center. By integrating directly with NetworkManager, GNOME allows users to convert their desktop or laptop into a wireless access point with minimal configuration. Beneath the user-friendly interface, GNOME coordinates network interfaces, IP address assignment, and firewall routing to distribute an active internet connection to connected client devices.

The Underlying Architecture: NetworkManager and D-Bus

GNOME Control Center (accessible as "Settings" in the application menu) does not manage network interfaces directly. Instead, it functions as a graphical front-end that communicates with NetworkManager via the system D-Bus.

When you configure a hotspot in the GNOME Wi-Fi panel:

  1. GNOME Control Center sends requests to NetworkManager to define a new connection profile.
  2. NetworkManager sets the connection mode to ap (Access Point) or adhoc (depending on hardware capabilities, though modern setups exclusively use AP mode).
  3. NetworkManager applies the shared IP method (IPv4/IPv6), which automatically triggers local routing, address assignment, and packet forwarding.

How to Create a Hotspot in GNOME Control Center

Managing and initiating a hotspot from the graphical interface requires only a few steps:

  1. Open Settings and navigate to the Wi-Fi panel.
  2. Ensure Wi-Fi is enabled.
  3. Click the menu button (represented by three vertical dots) in the window header bar.
  4. Select Turn On Wi-Fi Hotspot....
  5. A dialog appears allowing you to set the Network Name (SSID) and the Password (security defaults to WPA2-Personal).
  6. Click Turn On.

Once active, GNOME displays a dedicated panel showing the active network credentials alongside a scannable QR code, allowing mobile devices to join the network without manually entering the password.

Network Sharing and Routing Mechanisms

When the hotspot activates, GNOME and NetworkManager automate the underlying network plumbing:

  • Interface Modes: The wireless network card is shifted into Access Point (AP) mode using the nl80211 driver framework. This requires a wireless card that supports master/AP mode.
  • DHCP and DNS Allocation: NetworkManager launches an internal, lightweight instance of dnsmasq (or its internal DHCP server). This service assigns local IP addresses (typically in the 10.42.0.x/24 range) and provides DNS forwarding to connecting clients.
  • IP Forwarding and NAT: The Linux kernel enables IPv4 forwarding (net.ipv4.ip_forward = 1). NetworkManager dynamically configures packet filtering rules using iptables or nftables. Traffic originating from the hotspot subnet is masqueraded (NAT) through the active upstream interface—such as an Ethernet connection or a cellular modem.

Hardware and Operational Limitations

  • Single vs. Dual Wi-Fi Interfaces: If a device has only one Wi-Fi adapter that does not support simultaneous station and AP modes (Virtual AP/concurrency), activating the hotspot will disconnect the machine from its current Wi-Fi network. In this case, an upstream connection (such as Ethernet) is required to share the internet.
  • Wi-Fi Direct and Frequency Bands: GNOME generally defaults to standard 2.4 GHz channels for compatibility, though hardware permitting, it may utilize 5 GHz bands depending on regulatory domain settings configured in the system's crda or kernel wireless regulatory database.
