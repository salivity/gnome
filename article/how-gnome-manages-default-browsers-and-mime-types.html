How GNOME Manages Default Browsers and MIME Types

The GNOME desktop environment manages default web browsers and file associations by leveraging standardized Freedesktop.org specifications. Through a combination of MIME-type databases, .desktop entry files, user-specific override lists, and GNOME-specific configuration frameworks like GSettings, the system matches file formats and URI schemes to the appropriate applications. This article breaks down how GNOME determines file types, how configuration files prioritize defaults, and how web browsers are specifically registered and selected.

The Freedesktop.org Shared MIME-Info Standard

GNOME relies on the Shared MIME-Info specification defined by Freedesktop.org. When a user interacts with a file, the system determines its MIME type (such as text/html or application/pdf) by inspecting:

  1. File Extensions: Matching suffixes (e.g., .html, .png) against the database.
  2. File Signatures (Magic Numbers): Inspecting the initial bytes of a file when an extension is missing, ambiguous, or misleading.

The core MIME database resides in /usr/share/mime/. When applications are installed, they register new MIME definitions via XML files placed in /usr/share/mime/packages/, which are compiled using the update-mime-database command.

Desktop Entry Files (.desktop)

Applications announce their capabilities to GNOME via .desktop files stored in /usr/share/applications/ (system-wide) or ~/.local/share/applications/ (per-user).

Inside each .desktop file, the MimeType key lists all file types and protocol handlers the application can process. For example, a web browser’s .desktop entry typically includes:

MimeType=text/html;text/xml;application/xhtml_xml;x-scheme-handler/http;x-scheme-handler/https;

Without these definitions in its .desktop file, an application will not appear as an option for handling those specific formats within GNOME.

The mimeapps.list Hierarchy

The definitive mapping between MIME types and applications is recorded in mimeapps.list files. GNOME evaluates these files in a strict order of precedence, where earlier entries override later ones:

  1. ~/.config/mimeapps.list (User configuration)
  2. ~/.local/share/applications/mimeapps.list (Deprecated user location, supported for backward compatibility)
  3. /etc/xdg/mimeapps.list (System administrator configuration)
  4. /usr/share/applications/mimeapps.list (Distribution-level defaults)

A mimeapps.list file is divided into two primary sections:

  • [Default Applications]: Defines the primary application assigned to open a specific MIME type.
  • [Added Associations]: Defines secondary applications that appear in GNOME’s "Open With" context menus.

Default Web Browser Handling

Web browsers differ from standard file handlers because they must process both local file types and URL network protocols. To establish an application as the default browser, GNOME links it to:

  • File Types: text/html, application/xhtml+xml
  • URI Schemes: x-scheme-handler/http, x-scheme-handler/https

When you choose a default web browser in GNOME Settings > Default Applications, GNOME updates ~/.config/mimeapps.list with corresponding entries:

[Default Applications]
text/html=firefox.desktop
application/xhtml+xml=firefox.desktop
x-scheme-handler/http=firefox.desktop
x-scheme-handler/https=firefox.desktop

GNOME also references dconf keys stored under org.gnome.desktop.default-applications, though modern GNOME versions have largely unified around the x-scheme-handler MIME-type standard to ensure consistent behavior across other desktop environments and command-line tools.

Command-Line Tools for Inspection and Modification

GNOME's default associations can be queried and modified directly from the terminal using standard utilities:

  • Query the default browser for URLs: 
    xdg-mime query default x-scheme-handler/https
  • Set the default browser to a specific application: 
    xdg-mime default org.mozilla.firefox.desktop x-scheme-handler/http x-scheme-handler/https text/html
  • Inspect the handler using GIO (GNOME’s native virtual file system tool): 
    gio mime x-scheme-handler/https

By pairing the Freedesktop.org specifications with user-level configuration files, GNOME ensures that file associations remain predictable, customizable, and compatible with the broader Linux ecosystem.
