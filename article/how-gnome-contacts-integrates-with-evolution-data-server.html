How GNOME Contacts Integrates with Evolution Data Server

GNOME Contacts serves as a streamlined, dedicated graphical user interface for managing personal information, but it does not store or synchronize address book data on its own. Instead, it relies on Evolution Data Server (EDS), a robust backend system service that handles contact storage, protocol synchronization, and query management. This architectural separation allows GNOME Contacts to function as a centralized hub where contacts from various local and remote sources are aggregated and made accessible across the entire desktop environment.

The Client-Backend Architecture

The core of this integration is based on a client-server architecture where GNOME Contacts acts as the client and EDS operates as the background daemon. EDS runs persistent background processes—principally evolution-addressbook-factory—that manage the actual data manipulation.

GNOME Contacts communicates with this factory via libebook, a client library provided by the Evolution API, using D-Bus for inter-process communication (IPC). When GNOME Contacts opens, it does not read database files directly from the disk; instead, it requests data from EDS through standard D-Bus calls, ensuring that data access is thread-safe and non-blocking.

Centralized Source Management and GNOME Online Accounts

Evolution Data Server abstracts individual backends, enabling support for numerous protocols and services:

  • Local address books (stored in SQLite formats).
  • Remote cloud services (such as Google Contacts, Nextcloud, and generic CardDAV servers).
  • Enterprise directories (such as Microsoft Exchange, Office 365, and LDAP).

When a user adds an account through GNOME Online Accounts (GOA), the credentials and server endpoints are automatically provisioned inside EDS. GNOME Contacts automatically inherits these sources without requiring manual configuration. If an address book is added or modified in the full Evolution groupware suite, third-party email clients like Geary, or directly via GOA, EDS updates its internal registry, and the changes appear instantly in GNOME Contacts.

Unified Views and Meta-Contact Linking

A key feature of GNOME Contacts is its ability to present a clean, unified view of people whose details might be scattered across multiple accounts (e.g., an email address from a corporate LDAP directory and a personal phone number from a Google account).

Instead of forcing a destructive merge on the remote servers, GNOME Contacts uses EDS’s metadata capabilities. It links related contact records under a single "meta-contact" presentation. EDS tracks the individual underlying unique resource identifiers (UIDs) for each remote service while presenting a merged dataset to the UI, preserving the integrity of each independent source.

Real-Time Synchronization and System-Wide Sharing

The integration provides real-time event-driven updates. When a user creates, edits, or deletes a contact inside GNOME Contacts:

  1. GNOME Contacts invokes the appropriate libebook APIs.
  2. EDS writes the changes to the local cache and queues outbound synchronization to the respective remote server (such as pushing a CardDAV update).
  3. EDS emits change notification signals across the D-Bus system bus.
  4. Other integrated components—such as the GNOME Shell search provider, email clients, and calendar components—listen for these signals and immediately update their cached views.

By delegating networking, caching, and storage protocols to Evolution Data Server, GNOME Contacts maintains a lightweight footprint while providing a centralized, reliable address book ecosystem for Linux desktops.
