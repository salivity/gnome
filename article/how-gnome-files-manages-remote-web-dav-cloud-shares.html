How GNOME Files Manages Remote WebDAV Cloud Shares

GNOME Files, default known as Nautilus, manages remote cloud shares over WebDAV protocols by utilizing the GNOME Virtual File System (GVfs) backend. Rather than mounting remote storage at the kernel level like traditional network drives, GNOME Files integrates WebDAV into the desktop environment through user-space virtual backends, secure credential storage, and seamless abstraction for local applications. This article breaks down the underlying architecture, connection workflows, authentication mechanisms, and file transfer processes that enable GNOME Files to interact with WebDAV servers.

The Underlying Architecture: GVfs

The core technology behind GNOME Files' WebDAV support is GVfs (GNOME Virtual File System). GVfs operates in user space and communicates via D-Bus, an inter-process communication mechanism.

When managing WebDAV connections:

  • Backend Daemons: GVfs utilizes dedicated backend daemons—specifically gvfsd-dav for unencrypted WebDAV and gvfsd-davs for secure TLS/SSL-encrypted WebDAV.
  • Protocol Translation: These daemons translate standard file system requests (such as read, write, open, and delete) into HTTP/HTTPS methods (such as PROPFIND, GET, PUT, MKCOL, MOVE, and DELETE).
  • Desktop Virtualization: To the user inside GNOME Files, the remote server appears alongside local directories, hiding the complexities of the underlying HTTP requests.

Establishing a Connection

Users initiate a WebDAV connection in GNOME Files using the "Other Locations" panel.

  1. URI Resolution: The user inputs a Uniform Resource Identifier using the scheme dav:// (unencrypted) or davs:// (encrypted), followed by the host, port, and path (e.g., davs://example.com/remote.php/webdav/).
  2. Mounting via GIO: The file manager calls the GIO (GNOME Input/Output) library, which instructs the GVfs master daemon (gvfsd) to spawn the appropriate gvfsd-dav worker process.
  3. Capability Handshake: The daemon sends an OPTIONS HTTP request to the remote server to verify WebDAV compliance (Class 1, 2, or 3) and determine supported methods before browsing begins.

Authentication and Credential Storage

GNOME Files handles authentication without exposing raw passwords in configuration files.

  • Challenge-Response: When the WebDAV server returns a 401 Unauthorized status, GVfs intercepts the response and prompts the user for authentication credentials (supporting Basic, Digest, or token-based authentication).
  • GNOME Keyring Integration: Through the libsecret library, user credentials can be securely stored in the GNOME Keyring. On subsequent sessions, GVfs automatically fetches the stored secrets, mounting the WebDAV share without requiring user interaction.

Browsing and Metadata Management

Listing directories over WebDAV involves translating standard file attributes into WebDAV properties.

  • PROPFIND Queries: When navigating into a folder, the gvfsd-dav process issues an HTTP PROPFIND request with a depth header (Depth: 1) to retrieve file names, modification dates, content types, and file sizes.
  • Metadata Translation: XML responses returned by the server are parsed by the daemon and mapped to standard UNIX file attributes, allowing GNOME Files to display accurate icons, permissions, and timestamps.

File Transfers and Application Compatibility

Because WebDAV is layered over HTTP, GNOME Files treats file interactions differently than a traditional block or local storage system.

  • Streaming and Caching: For viewing small files, GVfs streams data directly into memory. For editing, the file is often downloaded to a local temporary cache, modified by the chosen application, and pushed back to the remote server via an HTTP PUT request upon saving.
  • The FUSE Bridge: Many non-GNOME applications rely on traditional POSIX system calls (open(), read(), write()) and cannot natively speak to the GIO/GVfs D-Bus interface. To bridge this gap, GVfs runs a FUSE (Filesystem in Userspace) daemon, exposing the mounted WebDAV share under /run/user/$UID/gvfs/ or ~/.gvfs. This allows any standard command-line utility or third-party application to interact transparently with the WebDAV share managed by GNOME Files.
