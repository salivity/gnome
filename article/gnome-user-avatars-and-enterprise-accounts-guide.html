GNOME User Avatars and Enterprise Accounts Guide

The GNOME desktop environment combines user-friendly graphical tools with low-level system daemons to manage identity and authentication. This article outlines how GNOME handles user avatar customization through AccountsService and the GNOME Control Center, as well as how it integrates with enterprise environments using technologies like Active Directory, FreeIPA, realmd, and SSSD.

User Avatar Customization in GNOME

GNOME provides an intuitive interface for setting and changing profile pictures through the Settings (gnome-control-center) application under the Users section. Users can select from a set of default stock illustrations, upload a custom local image file (such as PNG or JPEG), or capture a photo directly using a connected webcam.

Behind the graphical interface, avatar management is powered by AccountsService, a background D-Bus service that stores and tracks system user account data. When a user updates their picture:

  • The image is cropped and resized by the desktop interface.
  • AccountsService saves the image to the system directory /var/lib/AccountsService/icons/<username>.
  • The user's metadata configuration file located at /var/lib/AccountsService/users/<username> is updated with the path to the icon file.
  • Display managers such as GDM (GNOME Display Manager) read this data via D-Bus to display the avatar on the login and lock screens.

Enterprise User Account Integration

For enterprise environments, GNOME provides native domain-joining capabilities, enabling centralized authentication via Active Directory, FreeIPA, or general LDAP and Kerberos identity providers.

GNOME facilitates enterprise accounts through two main pathways:

  1. Initial Setup and Settings UI: In both GNOME Initial Setup (first-boot wizard) and GNOME Settings, administrators or users can select "Enterprise Login." Entering the domain name and credentials triggers a domain join directly from the desktop.
  2. Underlying Daemons (realmd and SSSD): GNOME communicates with realmd over D-Bus to discover and join enterprise domains. Once enrolled, SSSD (System Security Services Daemon) handles identity lookup, offline credential caching, and authentication policies (PAM and NSS integration).

Once joined, enterprise users can log directly into the workstation using their network credentials, generate Kerberos tickets automatically, and have their home directories created on demand.

Enterprise Avatars and Profile Synchronization

In an enterprise setup, avatar handling adapts to network identities:

  • Active Directory and LDAP Attributes: SSSD can be configured to fetch avatar data stored within directory attributes, such as jpegPhoto or thumbnailPhoto.
  • Local Overrides: If network accounts do not have directory-assigned images, users or administrators can still assign a local avatar using the standard GNOME Settings panel. AccountsService maps the network username to a local icon entry, allowing display customization without requiring write permissions to the central directory service.
