GNOME Fingerprint Authentication with fprintd

GNOME delivers seamless biometric authentication by integrating the fprintd daemon and its underlying library, libfprint, directly into core desktop components. This integration allows users to enroll their fingerprints through the native GNOME Settings application and subsequently use biometric verification for login screens, lock screens, and administrative privilege escalation via Polkit.

The Architecture: libfprint, fprintd, and PAM

GNOME does not interface with fingerprint hardware directly. Instead, it relies on a layered stack that abstracts the hardware and standardizes the authentication process:

  • libfprint: An open-source library that contains the low-level drivers required to communicate with supported fingerprint reader chipsets. It handles image processing, minutiae extraction, and template matching.
  • fprintd: A background daemon that wraps libfprint and exposes its functionality over the system D-Bus (net.reactivated.Fprint). This abstraction ensures that unprivileged desktop processes do not need direct access to raw hardware devices.
  • pam_fprintd: A Pluggable Authentication Module (PAM) that plugs into Linux's standard authentication subsystem, allowing fingerprint checks to satisfy login and authorization requests alongside or in place of passwords.

Fingerprint Enrollment in GNOME Settings

User enrollment is handled natively within the GNOME Control Center under the Users panel. When a compatible reader is detected via D-Bus, GNOME presents a "Fingerprint Login" option.

During enrollment:

  1. GNOME Settings makes a D-Bus request to fprintd to claim the device and start the enrollment session for a specific finger.
  2. The user is prompted to touch or swipe the sensor repeatedly.
  3. With each touch, libfprint builds a fingerprint template until it reaches sufficient sample quality.
  4. Once completed, fprintd stores the enrolled template locally (typically under /var/lib/fprint/ with restricted permissions) or writes it directly to the sensor's onboard storage if the hardware supports on-chip matching.

The Authentication Workflow

Once fingerprints are registered, GNOME integrates authentication across multiple desktop layers:

1. GDM and the Lock Screen

When GNOME Display Manager (GDM) or the GNOME Shell lock screen initializes, PAM triggers pam_fprintd. The lock screen displays a fingerprint icon indicating that the sensor is active. Touching the sensor sends an interrupt to the driver; libfprint verifies the scan against the stored template, and fprintd returns a success signal to PAM, immediately unlocking the session. If the scan fails, the interface falls back to standard password entry.

2. Privilege Escalation (Polkit)

When an application requests root privileges (such as installing software or modifying system settings), GNOME Shell invokes its Polkit authentication agent. Configured through PAM, the dialog prompts the user to either place their finger on the reader or enter their password. This standardizes security prompts across GUI utilities and terminal commands.
