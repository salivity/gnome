How GNOME Manages Flatpak Background Permissions

GNOME manages background application permissions for Flatpak packages through the XDG Desktop Portal framework, specifically using the Background portal. Because Flatpak isolates applications inside sandboxes, programs cannot silently spawn persistent background daemons or autostart on boot without explicit system clearance. GNOME acts as the front-end mediator, intercepting these background requests, enforcing user consent, and providing graphical interfaces to review and revoke background running privileges at any time.

The Role of XDG Desktop Portals

Flatpak enforces strict sandboxing rules that prevent applications from escaping their process tree or persisting after their graphical windows are closed. To run services or listeners in the background, a Flatpak app must communicate over D-Bus with the background portal (org.freedesktop.portal.Background), implemented on GNOME systems by xdg-desktop-portal-gnome.

When an application attempts to maintain a background service or register an autostart command, the portal queries the permission store. If the application has not yet been granted permission, GNOME prompts the user with an authorization dialog detailing the request.

Permission States and Storage

GNOME and the portal system store permission states in a centralized database managed by the xdg-permission-store. Background access generally falls into three states:

  • Allowed: The application is permitted to run without an active window and can wake up or stay alive in the background.
  • Denied: The application's request is blocked; processes attempting to remain alive after the primary window is closed may be terminated by the desktop session.
  • Ask: The portal prompts the user each time the condition is triggered until a permanent preference is set.

Applications can also request permission to run automatically at system login. This is handled concurrently through the same portal mechanism, ensuring autostart entries cannot be placed in user directories without the desktop environment's mediation.

Managing Permissions via GNOME Settings

Users can inspect and modify background permissions through the GNOME control center:

  1. Open Settings.
  2. Navigate to Apps.
  3. Select the desired Flatpak application from the list.
  4. Toggle the Run in Background switch to grant or revoke permission.

Disabling this option updates the permission store immediately. The next time the application attempts to keep background threads or services alive without an active window, the portal denies the operation.

Monitoring Active Background Services

Starting in GNOME 44, the GNOME Shell includes a dedicated "Background Apps" tracker inside the Quick Settings menu (top-right system menu).

When a Flatpak application runs without a visible window, GNOME Shell identifies the process via systemd application scopes and the portal service. The application appears in the menu with a close button, giving users real-time visibility into which sandboxed services are consuming system resources and allowing them to end the processes on demand.

Command-Line Control

For headless configurations or advanced management, Flatpak permissions can be queried and modified using the flatpak permission commands:

  • List background permissions: flatpak permissions
  • Reset an application's background permission: flatpak permission-reset <app-id>
  • Explicitly set permission: flatpak permission-set background background <app-id> yes (or no to block)

This combined architecture ensures that background services from sandboxed applications remain transparent, strictly governed, and entirely under user control.
