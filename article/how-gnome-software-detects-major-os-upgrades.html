How GNOME Software Detects Major OS Upgrades

GNOME Software streamlines the Linux desktop experience by identifying and notifying users when a new version of their operating system is ready for installation. This capability relies on an integrated architecture comprising modular plugins, background system services, distribution-specific metadata feeds, and desktop notification daemons. Together, these systems detect version changes upstream, evaluate system compatibility, and deliver actionable upgrade banners directly to the user.

Modular Plugin Architecture

At the core of GNOME Software's upgrade detection is its modular plugin system. Rather than implementing package management directly, GNOME Software communicates with underlying system package managers through dedicated plugins. Key plugins include:

  • PackageKit Plugin: Used on distributions like Fedora and openSUSE, this plugin interfaces with the PackageKit daemon to query remote repositories for new release lifecycles and metadata.
  • rpm-ostree and EOS Plugins: On immutable systems such as Fedora Silverblue or Endless OS, specialized plugins monitor tree commits and remote image branches to detect new base-system deployments.
  • Distribution-Specific Hooks: Certain distributions implement custom hooks (such as Ubuntu's release-upgrader integrations) that report upgrade availability directly through GNOME Software's API.

Scheduled Background Checks

GNOME Software runs a background service (gnome-software --gapplication-service) that periodically checks for software and OS updates. Driven by systemd user timers or network-connectivity triggers, the service refreshes repository caches without requiring the main graphical interface to be open. When high-bandwidth connections are detected, the system queries distribution mirrors to check whether a newer major target version has transitioned to a stable, supported state.

Metadata Parsing and Upgrade Definitions

For a major release to be detected, distribution maintainers publish upgrade metadata through channels like AppStream, PackageKit distribution configs, or dedicated distro APIs. When GNOME Software fetches repository data, it looks for specific release tags that indicate a higher operating system version than the current deployment.

The application parses these manifests to extract critical upgrade details, including:

  • The target version number and release name.
  • End-of-life status of the current release.
  • Release notes, developer changelogs, and promotional artwork.
  • Architectural requirements to ensure the machine can safely boot the new version.

Desktop Notifications and UI Banners

Once a valid upgrade path is verified, GNOME Software uses desktop communication protocols (FreeDesktop Notification specification) to notify the user. It sends a prioritized alert to GNOME Shell, displaying an interactive desktop notification stating that the next OS version is available.

Inside the GNOME Software application itself, the upgrade is given prominent visibility via a persistent banner at the top of the "Updates" page. This interface allows the user to download the required packages in the background and initiates the safe offline update mechanism upon reboot.
