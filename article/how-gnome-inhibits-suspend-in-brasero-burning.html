How GNOME Inhibits Suspend in Brasero Burning

Optical disc burning is an uninterrupted, real-time operation where any system interruption—such as entering sleep or suspend mode—corrupts the media and results in a failed write. To prevent this, GNOME coordinates with Brasero using system-level power management APIs and D-Bus interfaces to establish sleep inhibitors. This article explains how Brasero requests suspend inhibition, how GNOME processes and enforces this lock through systemd-logind and gnome-session, and how the system safely releases the lock once burning is finished.

When a write task begins, Brasero must guarantee continuous execution for external burning backends like growisofs, wodim, or cdrtools. Because optical media requires a steady stream of data to prevent buffer underruns, Brasero communicates with GNOME's session layer over D-Bus before the burning backend initiates.

Brasero requests an inhibitor lock by invoking the Inhibit method on the org.gnome.SessionManager D-Bus interface. The call includes four parameters: the application's name (Brasero), the window identifier of the running process, a human-readable reason (such as "Burning CD/DVD"), and a bitwise flag defining what to block. To prevent the computer from automatically sleeping or being manually suspended, Brasero specifies the flag corresponding to suspend inhibition (GSM_INHIBITOR_FLAG_SUSPEND).

Once the request is received, gnome-session generates a unique integer cookie, registers the inhibition, and returns the cookie to Brasero. In modern GNOME environments, gnome-session relays this constraint down to the system supervisor via systemd-logind. This is done by taking a sleep inhibitor lock through the org.freedesktop.login1.Manager interface using the Inhibit method, which holds open a specific file descriptor preventing the sleep target.

While this inhibitor is active, GNOME power settings and system-level triggers adjust their behavior:

  • Idle Timeouts: Automatic suspend triggers caused by user inactivity are suppressed for the duration of the burn.
  • Power Key Events: Normal suspend actions initiated by pressing the hardware sleep button are ignored or blocked.
  • Lid Close Actions: Depending on the system's logind.conf configuration (specifically HandleLidSwitch), closing a laptop lid will either be ignored or delayed to ensure the disc is not ruined.

When the burning process completes—or if the operation aborts due to an error—Brasero calls the Uninhibit method on org.gnome.SessionManager, passing the cookie it received at the start. GNOME then drops the registration and closes the corresponding file descriptor with systemd-logind. If Brasero crashes unexpectedly, the D-Bus connection drops automatically, causing the GNOME session manager to immediately release the inhibitor lock and return normal power management behavior to the system.
