GNOME Files Search by File Size and Date

GNOME Files (Nautilus) offers built-in search capabilities that allow users to locate files across directories using a combination of direct directory traversal and background indexing engines. This article explains how GNOME Files processes searches, how to utilize the graphical interface for modification timestamp filters, how file size is addressed within search results, and how to work around interface limitations for size-specific queries.

Search Architecture in GNOME Files

GNOME Files executes searches through two primary mechanisms depending on the directory:

  1. Tracker Indexing: For default user directories (such as Documents, Downloads, and Pictures), GNOME Files relies on Tracker (or Localsearch in newer GNOME releases). Tracker monitors the file system and pre-indexes metadata, including file names, MIME types, modification dates, and sizes, allowing for near-instant retrieval.
  2. Recursive Direct Search: For unindexed directories, network shares, or external drives, GNOME Files falls back to standard recursive crawling. In this mode, the application scans the directory tree in real time, inspecting file attributes directly via standard POSIX system calls.

Searching by Modification Timestamps

Filtering by modification date is natively integrated into the GNOME Files user interface:

  1. Press Ctrl + F or click the magnifying glass icon to initiate a search.
  2. Type a search query, or leave the input empty to evaluate all files in the current directory and its subdirectories.
  3. Click the filter button (represented by a drop-down arrow or filter sliders adjacent to the search field).
  4. Locate the When filter section.
  5. Select a predefined range, such as Last hour, Today, This week, This month, or This year. Some GNOME versions also allow setting custom date ranges.

When a timestamp filter is selected, GNOME Files restricts the result set to files whose metadata matches the specified date boundary, querying the Tracker database or checking the mtime (modification time) file attribute during real-time directory traversal.

Searching by File Size

Unlike modification timestamps and file types, the GNOME Files graphical search interface does not include an explicit filter drop-down for file size (such as "greater than" or "less than" a specific megabyte threshold). Instead, size handling during searches occurs through the following methods:

  • Sorting Search Results: Once a search is executed, switch to the List View (using the view toggle icon or Ctrl + 2). Click the Size column header to sort the resulting list in ascending or descending order. This organizes matched files by size even if the query itself did not filter them out.
  • Tracker Querying (Command Line): Because Tracker records size metadata, users needing exact size filters can query the underlying database via the terminal using the tracker3 CLI utility to locate files by size criteria that the Nautilus GUI does not expose.
  • System Utilities for Size-Specific Searches: For complex file size queries (such as finding all files larger than 1 GB), GNOME integrates with the Disk Usage Analyzer (Baobab) to visually identify oversized files, or users can run standard terminal commands like find /path/to/folder -size +100M to complement the desktop environment's file manager.
