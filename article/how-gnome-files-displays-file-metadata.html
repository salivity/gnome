How GNOME Files Displays File Metadata

GNOME Files, default known as Nautilus, provides native support for reading and displaying rich file metadata, including image dimensions, audio bitrates, video durations, and camera EXIF information. By integrating closely with the GNOME desktop's underlying media and indexing frameworks, the file manager extracts this embedded information automatically and exposes it through detailed property windows, configurable list-view columns, and tooltip previews.

The Properties Window

The primary method for viewing comprehensive metadata in GNOME Files is through the file properties dialog:

  1. Right-click on any supported file (such as a JPEG, MP3, or MP4) and select Properties.
  2. For rich media, GNOME Files displays dedicated metadata tabs—such as Audio, Video, or Image—alongside the standard Basic and Permissions tabs.

Within these tabs:

  • Audio files: Displays the bitrate, sample rate, channels, duration, artist, album, and track number read directly from ID3, Vorbis, or FLAC tags.
  • Image files: Displays image dimensions (pixel width and height), color profiles, and camera EXIF data (e.g., exposure time, focal length, ISO, and device model).
  • Video files: Displays the resolution, framerate, video/audio codecs, container format, and total runtime.

Configurable List View Columns

GNOME Files allows users to view metadata directly alongside file names in its List View layout:

  1. Switch the view mode to List View.
  2. Open the view options or preferences menu and select Visible Columns.
  3. Enable columns relevant to metadata, such as Dimensions, Duration, or Created.

When enabled, attributes like video length or picture size appear inline in the directory listing, allowing for quick sorting without opening individual file properties.

The Underlying Architecture

GNOME Files does not implement separate file parsers for every format. Instead, it relies on shared GNOME subsystems to read and cache metadata efficiently:

  • Tracker (LocalSearch): GNOME's indexing engine scans directories in the background using lightweight miners. It extracts metadata into a local database, allowing Nautilus to retrieve properties quickly without re-parsing large files each time a folder is opened.
  • GStreamer: Media extractors use the GStreamer framework to parse headers for audio and video streams, ensuring broad codec compatibility.
  • Specialized Libraries: Image metadata (such as EXIF, IPTC, and XMP) is parsed using dedicated libraries like libexif and exempi.

Performance Optimizations

To avoid interface slowdowns, GNOME Files restricts automatic metadata extraction and thumbnailing under certain conditions. Users can configure thumbnail and metadata generation behavior under Preferences > Performance, limiting deep file inspection to local storage only or capping it to files below a specific file size threshold. On remote network shares (e.g., SMB or SFTP), metadata generation is often minimized by default to conserve bandwidth and maintain responsive directory navigation.
