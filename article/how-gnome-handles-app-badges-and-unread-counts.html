How GNOME Handles App Badges and Unread Counts

GNOME Shell handles application badges and unread counts differently than traditional desktop operating systems, opting by default not to display numeric badges on pinned Dash icons. While upstream GNOME restricts unread indicators to its centralized notification shade, the desktop environment can expose icon-level badge counts through specific background D-Bus protocols leveraged by shell extensions and downstream distribution docks.

Upstream GNOME Philosophy and Default Behavior

Vanilla GNOME Shell intentionally lacks native support for unread count badges on its Dash icons. GNOME's human interface guidelines emphasize a minimal, distraction-free computing environment, actively discouraging persistent ambient counters that demand attention.

In a default GNOME installation, when an application receives a message or alert:

  • A transient notification banner appears at the top of the display.
  • If ignored, the notification persists in the central Notification Center (accessible via the date and clock in the top bar).
  • The Dash icon itself remains completely static, offering no numeric indicators or status dots.

The Underlying Protocol: Unity LauncherEntry API

Even though default GNOME does not render badges, many Linux-native and cross-platform applications (including Thunderbird, Slack, Telegram, and Discord) still broadcast unread counts and progress bars. They accomplish this by emitting signals over the D-Bus system using the com.canonical.Unity.LauncherEntry interface.

Originally created by Canonical for Ubuntu’s legacy Unity desktop, this API became the de facto standard on Linux for application badge reporting. When an app receives an unread message, it sends a D-Bus signal updating properties like count and count-visible.

How Downstream Implementations Show Badges

Distributions and users who prefer numeric badges bridge the gap between application D-Bus signals and the desktop interface:

  • Ubuntu Dock: Ubuntu ships a customized GNOME Shell with the Ubuntu Dock extension enabled out of the box. This extension actively listens to the com.canonical.Unity.LauncherEntry D-Bus path. When an application reports a count, Ubuntu Dock overlays a numeric counter bubble directly onto the pinned or running launcher icon.
  • GNOME Extensions: On non-Ubuntu distributions (such as Fedora or Arch Linux), users can restore badge functionality by installing third-party extensions. Extensions such as Dash to Dock or Dash to Panel include native listeners for the Unity Launcher API, allowing users to toggle unread badges, customize badge colors, and manage progress bars on their Dash icons.
