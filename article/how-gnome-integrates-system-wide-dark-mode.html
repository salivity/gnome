How GNOME Integrates System-Wide Dark Mode

GNOME integrates system-wide dark mode using a standardized cross-desktop specification that communicates appearance preferences across modern toolkits and sandboxed applications. Through the Freedesktop.org XDG Desktop Portal and modern GTK libraries, GNOME exposes a single configuration switch that automatically adjusts native GNOME software, web browsers, Qt applications, and Electron clients without requiring application restarts or custom theme hacking.

The Freedesktop.org Settings Portal

At the core of GNOME’s dark mode implementation is the org.freedesktop.impl.portal.Settings D-Bus interface, managed by xdg-desktop-portal-gnome. When a user toggles the dark style switch in GNOME Settings or the Quick Settings menu, GNOME updates the color-scheme key within the org.gnome.desktop.interface GSettings schema.

The GNOME portal backend detects this change and broadcasts it across the session bus via the standard Freedesktop Appearance portal. This design creates an abstraction layer that allows sandboxed applications (such as Flatpaks) and non-GNOME software to safely query and listen for the system's preferred color scheme (0 for default/light, 1 for dark, and 2 for light-preferring).

Native GTK4 and Libadwaita

Native GNOME applications built with GTK4 and Libadwaita offer the tightest integration with the dark style preference:

  • Automatic Style Switching: Libadwaita monitors the color-scheme preference directly. When the preference shifts, Libadwaita hot-reloads its dynamic CSS stylesheets, updating the UI instantly without interrupting the user's workflow.
  • Granular Developer Control: Application developers can override the system default when necessary (e.g., image editors or video players that default to dark interfaces) while still honoring user preferences via the AdwStyleManager API.

Web Browsers and Electron Applications

Web browsers and Electron-based tools integrate with GNOME's dark mode through standard web APIs:

  • CSS Media Queries: Browsers like Mozilla Firefox and Chromium-based browsers (Google Chrome, Brave, Microsoft Edge) listen to the XDG portal's color-scheme property.
  • Prefers-Color-Scheme: When the portal reports a dark state, the browser sets the CSS @media (prefers-color-scheme: dark) media feature to true, prompting websites and web-based applications to display their dark themes automatically.

Qt and Legacy GTK3 Integration

Because GNOME phased out the older approach of forcibly switching GTK themes (such as swapping between Adwaita and Adwaita-dark), handling cross-toolkit software requires targeted compatibility layers:

  • Qt 6.5 and Newer: Modern Qt versions feature native support for the Freedesktop appearance portal, allowing Qt applications to automatically match GNOME’s dark setting if a compatible Qt style plugin is installed.
  • GTK3 Applications: Traditional GTK3 applications do not natively support the Freedesktop color-scheme portal. To address this, GNOME includes a compatibility bridge in xdg-desktop-portal-gnome that can toggle the legacy gtk-application-prefer-dark-theme setting, ensuring older software applies a dark variant if the active GTK3 theme supports it.
