How GNOME Papers Modernizes the Evince Document Viewer

GNOME Papers represents the next-generation evolution of Evince, the long-standing default document viewer for the GNOME desktop environment. While Evince served reliably for nearly two decades, its aging codebase struggled to adapt to modern desktop standards. This article explores how Papers revitalizes this core utility by transitioning to GTK4 and Libadwaita, adopting the Rust programming language, streamlining the user interface, and leveraging modern rendering pipelines for improved performance and security.

Migration to GTK4 and Libadwaita

The most significant change in GNOME Papers is the complete architectural migration from GTK3 to GTK4 and Libadwaita. Evince relied heavily on outdated widget structures and drawing models, making modern feature implementation difficult.

By building upon GTK4, Papers utilizes a fully hardware-accelerated rendering pipeline powered by Vulkan or OpenGL. This eliminates the sluggishness often experienced in legacy Evince when scrolling through complex, graphic-heavy PDF files. Furthermore, Libadwaita ensures that the application follows the latest GNOME Human Interface Guidelines, offering adaptive layouts that scale gracefully from standard desktop monitors down to mobile screens such as the Librem 5 or PinePhone.

Memory Safety and Backend Modernization with Rust

Legacy Evince is written entirely in C, a language prone to memory safety vulnerabilities—a major concern for document viewers that parse complex, potentially malicious file formats like PDF, PostScript, and XPS.

GNOME Papers modernizes this foundation by rewriting key components in Rust. Integrating Rust introduces memory safety guarantees at compile time, drastically reducing the attack surface for common exploits such as buffer overflows and use-after-free bugs. While it still connects to robust parsing backends like Poppler, the application scaffolding and internal state management benefit from Rust’s modern concurrency features and strict type system.

Streamlined User Interface

Evince’s design reflected desktop paradigms from the mid-2000s, often leading to visual clutter with traditional menu bars, detached search panels, and rigid sidebars. Papers redesigns the entire interaction model:

  • Header Bar Integration: Document titles, primary actions, and viewing modes are unified into a compact, responsive header bar.
  • Modernized Navigation: The sidebar for thumbnails, bookmarks, and document outlines now uses modern list views that load asynchronously, keeping the interface fluid even with documents containing thousands of pages.
  • Touch and Gesture Support: GTK4’s event controllers give Papers native support for multi-touch gestures, enabling smooth pinch-to-zoom and kinetic scrolling on trackpads and touchscreens.

Sandboxing and Modern Packaging

Evince was initially conceived before modern sandboxing frameworks existed, requiring extensive legacy workarounds to isolate document parsing. GNOME Papers is built with modern distribution channels in mind, primarily targeting Flatpak and Wayland out of the box. This architecture enforces strict security boundaries via Flatpak portals, ensuring that document viewing remains isolated from the rest of the host operating system.
