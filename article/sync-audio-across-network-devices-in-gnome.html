Sync Audio Across Network Devices in GNOME

GNOME manages multi-device audio output synchronization across local networks by leveraging its underlying modern sound server, PipeWire, alongside legacy PulseAudio network modules. Through network streaming protocols, automated service discovery, and clock-synchronization algorithms, GNOME allows a single system to broadcast audio to multiple endpoints—such as networked speakers, media centers, or other PCs—while keeping playback aligned and minimizing latency drift.

The Underlying Engine: PipeWire and PulseAudio

GNOME does not process audio streams directly; instead, the GNOME Control Center interfaces with the system's sound server. Modern Linux distributions running GNOME use PipeWire as the default multimedia framework, often replacing or wrapping PulseAudio.

When synchronizing audio over a local area network (LAN), the sound server creates virtual output devices (sinks). These network sinks capture local audio streams and package them into network packets, dispatching them to remote receiving nodes running compatible daemon instances.

Clock Synchronization and Drift Compensation

The primary challenge in multi-device network playback is clock drift—the tendency of independent hardware clocks to run at slightly different speeds, resulting in echo or phase issues. GNOME-compatible audio servers address this using specialized streaming protocols:

  • RTP/multicast: Real-time Transport Protocol (RTP) multicast broadcasts a single audio stream to multiple clients on the subnet simultaneously. Synchronization is maintained using standard RTCP (RTP Control Protocol) sender and receiver reports, which calculate round-trip times and synchronize playback timestamps.
  • The ROC Toolkit: PipeWire integrates with the ROC streaming system (libpipewire-module-roc-sink). ROC is designed specifically for real-time network audio and features robust clock synchronization. It actively tracks clock drift between the sender and receiver, applying adaptive resampling in real time to stretch or compress the audio buffer without perceptible pitch changes. Additionally, ROC employs Forward Error Correction (FEC) to recover lost packets without requiring retransmission delays.
  • RAOP (AirPlay): PulseAudio and PipeWire support Apple's Remote Audio Output Protocol (RAOP). This protocol relies on Precision Time Protocol (PTP) / NTP-style handshakes to enforce strict timing across supported AirPlay devices on the local network.

Service Discovery via Zeroconf/Avahi

Network sinks are dynamically detected and presented to GNOME using mDNS/DNS-SD, implemented on Linux through Avahi. When remote audio targets (such as networked PulseAudio servers or Snapcast endpoints) broadcast their presence on the local network, the local audio daemon registers them automatically.

Once discovered, these endpoints appear alongside physical sound cards in the GNOME Settings audio panel. Combined sinks can then be constructed using configuration utilities or tools like pactl, grouping multiple network endpoints into a single selectable output.

Combined Sinks and Unified Playback

To stream to multiple devices simultaneously, the sound server creates a combined sink module (module-combine-sink). When the user selects this combined sink in GNOME, the audio server clones the primary output stream and feeds it into each member sink concurrently. The server calculates the maximum latency buffer across all connected devices and automatically delays faster streams to ensure all physical and networked devices emit sound in near-perfect phase alignment.
