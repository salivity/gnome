How GNOME Updates Systems via PackageKit and OSTree

GNOME delivers seamless and stable system updates by moving away from risky in-session patching toward robust offline update models. Through GNOME Software, the desktop environment coordinates with PackageKit on traditional distributions and OSTree on immutable platforms to download updates in the background and stage them for deployment. This article explains how GNOME implements offline update mechanisms to eliminate application crashes, maintain file system consistency, and provide a friction-free user experience across various Linux architectures.

The Need for Offline Updates

Updating a running Linux system—often called an "online update"—can lead to instability. When shared libraries, desktop components, or the Linux kernel are modified while applications are actively reading them from disk, programs can crash, enter undefined states, or fail to restart properly.

To eliminate this vulnerability, GNOME adopted an "offline update" model. Instead of swapping files while the user is actively working, the desktop environment downloads the required data in the background, prepares the update sequence, and applies changes when critical system processes are not running.

How PackageKit Powers Traditional Offline Updates

On standard package-managed distributions like Debian, Ubuntu, and standard Fedora, GNOME Software interfaces with PackageKit via D-Bus to handle offline updates.

  1. Background Staging: GNOME Software periodically queries PackageKit for available updates. When found, PackageKit downloads the relevant .deb or .rpm packages in the background without affecting the active session.
  2. Setting the Trigger: Once downloaded, GNOME prompts the user to "Restart & Update." When selected, PackageKit creates a symlink target (traditionally /system-update) and schedules a specialized systemd boot sequence using system-update.target.
  3. Isolated Execution: Upon reboot, systemd detects the update target and boots into an isolated environment instead of loading the graphical desktop session. The system mounts the file systems and executes the PackageKit offline update service, which unpacks and installs the packages safely without interference from active user sessions.
  4. Finalization: Once the package transaction concludes successfully, the temporary update trigger is removed, and the system automatically performs a standard reboot directly into the newly updated environment. If an error occurs, the process can gracefully abort or log the failure for administrative review.

How OSTree Delivers Atomic Operating System Updates

On modern immutable distributions such as Fedora Silverblue, Fedora Kinoite, and Endless OS, GNOME integrates with OSTree (or rpm-ostree) instead of traditional package managers. OSTree functions like "git for operating system binaries," treating the root filesystem as a version-controlled tree.

  1. Deploying Commit Trees: When an update is detected, GNOME Software triggers OSTree to pull down the newly updated image layers in the background. Because OSTree uses content-addressed object storage, this operation executes completely in user space without touching the active root directory.
  2. Staging the New Deployment: OSTree creates a new root deployment tree alongside the currently running one and updates the bootloader configuration (such as GRUB) so the new deployment boots by default on the next start.
  3. Instantaneous Activation: Because the new operating system image is assembled while the system is still running, there is no need for a lengthy "installing updates" screen on reboot. The user simply reboots the computer, the bootloader points to the new deployment, and the update takes effect immediately.
  4. Built-in Rollbacks: If an update fails to boot or introduces bugs, the previous deployment remains untouched on the drive. Users can effortlessly roll back to the exact previous state from the GRUB menu or GNOME Software interface.

Unifying the Experience in GNOME Software

GNOME Software acts as the unified presentation layer that abstracts these complex backend mechanisms. Whether the underlying operating system utilizes PackageKit or OSTree, the user encounters the exact same interface: updates are discovered quietly, downloaded without interrupting active workflows, and applied safely either through a quick reboot or an isolated systemd maintenance phase. This integration ensures operating system reliability without forcing users to manage terminal commands or risk running unstable, partially updated desktop sessions.
