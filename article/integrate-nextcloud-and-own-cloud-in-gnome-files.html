Integrate Nextcloud and ownCloud in GNOME Files

GNOME Files, commonly known as Nautilus, natively integrates with self-hosted cloud platforms like ownCloud and Nextcloud to provide direct access to remote data. This integration relies on the GNOME desktop ecosystem’s built-in framework, utilizing GNOME Online Accounts to authenticate and GVfs to mount remote directories over standard network protocols. Users can browse, edit, and organize their remote files directly from the desktop file manager without needing third-party desktop synchronization clients.

GNOME Online Accounts (GOA)

The foundation of the integration is GNOME Online Accounts. Rather than configuring connections directly inside the file manager, the desktop uses a centralized credential manager located in the system settings.

When configuring a Nextcloud or ownCloud account, GOA prompts the user for the server address, username, and an authentication password or app token. Once verified, GOA acts as a single sign-on mechanism. It detects the services exposed by the server instance and provisions access across multiple desktop components simultaneously, including GNOME Files, GNOME Calendar (via CalDAV), and GNOME Contacts (via CardDAV).

The GVfs Architecture and WebDAV

GNOME Files interacts with the remote server using GVfs (GNOME Virtual File System), the virtual filesystem abstraction layer designed for the GNOME desktop.

Nextcloud and ownCloud both use WebDAV (Web Distributed Authoring and Versioning) as their underlying communication protocol for file handling. When an account is registered in GOA, GVfs mounts the user’s remote storage endpoint using the davs:// (secure WebDAV) URI scheme. The remote storage is represented internally at a path typically structured under /run/user/<UID>/gvfs/, allowing the operating system to map remote network requests into standard POSIX-like file operations.

File Manager Interface and User Experience

Once mounted, the cloud instance appears as a distinct volume in the GNOME Files sidebar under the network or remote locations section.

Users can interact with remote directories as if they were local folders. Operations such as opening documents, renaming files, creating folders, and moving items via drag-and-drop are translated in real time into corresponding HTTP/WebDAV methods (GET, PUT, MOVE, PROPFIND, and DELETE). Applications supporting the GIO/GVfs API can open and save files directly to the cloud without creating intermediate manual transfers.

Network Mounting vs. File Synchronization

It is important to distinguish GNOME Files' native integration from official desktop sync clients. GNOME Files provides a real-time network mount rather than a local mirror:

  • Bandwidth and Storage: Files remain on the remote server and are fetched on demand. This saves local disk space because files are not duplicated on the host drive.
  • Network Dependency: Because files are streamed directly over WebDAV, an active internet connection is required to browse directories and open documents.
  • Offline Access: Unlike dedicated ownCloud or Nextcloud desktop clients, the GVfs integration does not maintain an offline cache or perform background two-way synchronization.

This native approach provides a lightweight, integrated solution for interacting with Nextcloud and ownCloud infrastructure directly within standard Linux desktop workflows.
