How GNOME Handles Monitor Hotplugging and Displays

GNOME manages monitor hotplugging and multi-display arrangements through a coordinated stack involving the Linux kernel, the Mutter compositor, and the GNOME Control Center. When displays are connected or reconfigured, the system automatically detects hardware state changes, recalls previously saved monitor profiles via hardware identifiers, and applies layout configurations through a unified virtual coordinate space.

Hardware Detection and Hotplugging Architecture

Monitor hotplugging begins at the kernel level. The Linux kernel's Direct Rendering Manager (DRM) and Kernel Mode Setting (KMS) drivers detect physical changes in connection states—such as plugging in an HDMI, DisplayPort, or USB-C cable—through hotplug interrupt events.

Once a hardware change occurs, the kernel broadcasts a udev event to user space. Mutter, GNOME’s window manager and compositor, listens for these events. Under Wayland, Mutter acts directly as the display server, querying the DRM subsystem to retrieve Extended Display Identification Data (EDID) from the newly connected display. Under X11, Mutter achieves similar detection via the XResize, Rotate and Reflect Extension (XRandR).

Configuration Storage and Profile Matching

GNOME avoids forcing users to reconfigure displays upon reconnection by caching multi-monitor setups. When a display is detected, Mutter reads its EDID, which contains unique identifiers such as manufacturer name, product code, and serial number.

Mutter cross-references these identifiers against an internal database saved in ~/.config/monitors.xml. This XML file stores:

  • The relative spatial position \((X, Y)\) coordinates of each screen.
  • Active resolutions and refresh rates.
  • Scaling factors (standard and fractional).
  • Rotation and orientation (standard, portrait, inverted).
  • The designated primary display.

If a connected combination of monitors matches an existing profile in monitors.xml, GNOME applies those saved parameters instantly without user intervention. If an unknown display is connected, GNOME defaults to a safe extension mode, placing the new display to the right of the active desktop.

Multi-Display Arrangement in GNOME Settings

Users configure and customize multi-monitor environments via the GNOME Control Center under the Displays panel. This interface provides an interactive, visual representation of the connected displays, translating user actions into compositor instructions.

  • Spatial Canvas Placement: Displays exist on a continuous virtual canvas. Users can drag and reorder screen blocks horizontally or vertically. GNOME assigns coordinate offsets \((X=0, Y=0)\) to the top-left corner of the primary display or overall bounding box, aligning subsequent displays relatively to prevent dead zones where the mouse cursor cannot cross.
  • Display Modes: GNOME allows users to select between "Join Displays" (an extended desktop offering unique workspaces) and "Mirror" (cloning identical output streams across all active monitors matching the lowest common denominator resolution).
  • Primary Monitor Assignment: The Settings interface allows designating a primary monitor. The top bar, application notifications, and default overview launch points align with this designated display.
  • Per-Monitor Scaling: In Wayland sessions, GNOME supports independent per-monitor scaling and fractional scaling. This allows high-DPI displays (such as 4K laptop screens) to run at 150% or 200% scale while maintaining 100% native scale on adjacent 1080p external monitors without blurring.
