GNOME User Switching Without Ending Active Sessions

The GNOME desktop environment allows multiple users to remain logged in simultaneously without terminating ongoing processes through a coordinated architecture involving the GNOME Display Manager (GDM), systemd-logind, and display server resource arbitration. When a user chooses to switch accounts, GNOME does not log out the current user; instead, it retains the active session's state in memory, relinquishes access to physical input and output hardware, and prompts GDM to spawn or switch to another graphical session. This article explains the technical mechanisms behind this seamless user switching.

Session Management with systemd-logind

The core of session persistence in modern Linux distributions running GNOME is systemd-logind. Whenever a user logs in, systemd-logind creates a distinct session registered under a dedicated user slice (user-<UID>.slice).

All applications, background tasks, and desktop components launched by the user belong to control groups (cgroups) under this user slice. Because these processes are tied to the systemd user instance rather than the active display hardware, they continue running in the background even when the display is switched away from their graphical environment.

The Role of GDM (GNOME Display Manager)

GDM handles the authentication interface and manages the graphical lifecycles of user sessions. When a user requests a switch:

  1. GNOME Shell sends a D-Bus call to GDM requesting user switching.
  2. GDM either activates an existing session belonging to another user or launches its own display greeter session on an available Virtual Terminal (VT) or display seat.
  3. GDM keeps the original session alive in the background rather than issuing a session termination signal (SIGTERM or SIGHUP).

Virtual Terminals and Hardware Access Control

Physical screen and input device assignment are mediated via Linux Virtual Terminals (VTs) and Direct Rendering Manager (DRM) subsystem controls:

  • X11 Environments: Traditionally, GDM allocates separate Virtual Terminals (e.g., VT7, VT8) for each concurrent graphical session. When switching users, systemd-logind simply switches the active VT. The inactive user's X server pauses rendering to the screen, while the active user's X server takes control of the physical display.
  • Wayland Environments: Under Wayland, the GNOME Shell compositor (Mutter) interacts directly with systemd-logind using the logind D-Bus API to manage device file descriptors. When a switch occurs, systemd-logind revokes DRM master permissions and input device access from the current session's compositor and transfers them to the target session. Mutter pauses its rendering pipeline, retaining the desktop buffers in video memory (VRAM) and system RAM.

Process Continuity and Resource Retention

Because the kernel retains process memory and systemd maintains the user session, all running tasks—such as long-running scripts, downloads, and unsaved documents—persist uninterrupted. When the original user logs back in, GDM re-engages their session, systemd-logind restores input and DRM access, and GNOME Shell resumes rendering the desktop exactly as it was left.
