How GNOME Shell Renders CSD Shadows and Blur

This article explores the technical pipeline GNOME Shell and its underlying compositor, Mutter, use to draw drop shadows and blur effects around client-side decorated (CSD) windows. It breaks down how the compositor negotiates window geometry, delegates shadow rendering between the client and the compositor, and applies GPU-accelerated post-processing shaders to achieve background blur effects.

Window Geometry and Extent Negotiation

With Client-Side Decorations (CSD), the application—typically using GTK—is responsible for drawing its own header bars, window controls, and borders. Because the client often manages the visual boundary, it must communicate where the actual interactable window ends and where decorative padding begins.

On Wayland, GTK achieves this using the xdg_shell protocol through xdg_surface.set_window_geometry. On X11, it uses the _GTK_FRAME_EXTENTS property. This negotiation defines an invisible offset margin around the window frame. By passing these dimensions to Mutter (GNOME's window manager and compositor), the system knows exactly which portions of the surface are interactive, where window snapping edges reside, and where drop shadows or transparent effects belong.

How Drop Shadows Are Rendered

Drop shadows for CSD windows can be handled in two distinct ways depending on the window type and display protocol:

  1. Client-Rendered Shadows (Standard CSD):
    In standard GTK3 and GTK4 applications, the drop shadow is actually drawn by the client itself, not Mutter. The application allocates an oversized surface buffer that extends beyond the visible window frame. GTK’s rendering engines (such as GSK in GTK4 or Cairo in GTK3) compute the drop shadow using CSS properties like box-shadow. The shadow is rendered directly into the transparent margins of the application's surface. When Mutter composites the screen, it treats the shadow as standard pixel data within the window's bounding box, relying on the negotiated frame extents to prevent input events on the shadow itself.

  2. Compositor-Rendered Shadows (MetaShadowFactory):
    For windows that do not draw their own shadows (such as server-side decorated windows or specific legacy surfaces), Mutter takes control using MetaShadowFactory. The compositor calculates a Gaussian-blurred rectangle based on the window's shape, caches it as a 9-slice texture (corners and edges), and composites it behind the window actor using Cogl, Clutter’s hardware-abstraction library.

How Blur Effects Are Applied

Blur effects behind transparent CSD elements (such as header bars or sidebars) are not handled by the client application alone. Because an application cannot see the contents of windows behind it for security and architectural reasons, the compositor must render the background blur.

GNOME Shell implements background blur using Clutter’s actor pipeline and GLSL (OpenGL Shading Language) shaders via the following process:

  1. Background Capture: When an actor requests background blur (handled in the compositor via ShellBlurEffect), Mutter binds an offscreen Framebuffer Object (FBO). It captures the region of the scene graph directly underneath the target window before drawing the window itself.
  2. Downsampling: To maintain a smooth 60 or 140+ FPS frame rate, the captured background texture is often downscaled to a lower resolution. Blurring fewer pixels significantly reduces GPU memory bandwidth.
  3. Multi-Pass Filtering: The downsampled texture is passed through a multi-stage fragment shader. GNOME Shell typically utilizes a dual-Kawase blur or a multi-pass separable Gaussian blur. This approach applies horizontal and vertical blur passes sequentially, expanding the blur radius efficiently without overwhelming the GPU.
  4. Upsampling and Composition: The blurred texture is upsampled back to target scale and rendered into the scene.

Final Scene Assembly

Once the drop shadow buffer (from the client surface) and the blurred background texture (from the compositor's FBO pass) are prepared, Mutter's rendering pipeline combines them. The blurred texture is drawn first, followed by the client surface containing the window contents and the drop shadow. Cogl uses standard alpha-blending equations (GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA) to composite all layers onto the screen seamlessly, creating cohesive depth without visual artifacts.
