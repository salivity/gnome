How GNOME Design Team Vets Core App Interfaces

The GNOME Design Team serves as both a mentor and a quality gatekeeper for software aspiring to become a GNOME Core application. Before an app is accepted into the core suite, the design team rigorously evaluates its user interface, workflows, and adherence to platform standards to ensure the entire operating environment remains coherent, accessible, and focused. Through close collaboration, iterative reviews, and strict interface standards, the team ensures that only software providing a seamless user experience receives core status.

Enforcing the Human Interface Guidelines (HIG)

The primary benchmark for any core candidate is the GNOME Human Interface Guidelines (HIG). The Design Team evaluates the application to ensure it implements standardized design patterns. This includes:

  • Standard Controls: Verifying the proper use of Header Bars, primary menus, and platform-standard widgets provided by GTK and Libadwaita.
  • Adaptive Layouts: Ensuring the interface dynamically scales and adapts across various display sizes, aspect ratios, and mobile form factors.
  • Visual Consistency: Ensuring typography, iconography, spacing, and styling integrate seamlessly with the rest of the GNOME desktop.

Applications that introduce custom widgets or non-standard interaction models are directed to adjust their interfaces to fit standard GNOME design patterns.

Streamlining Workflows and Feature Scoping

GNOME prioritizes simplicity and task-oriented design over feature bloat. The Design Team scrutinizes the application's overall purpose and feature set, ensuring the app solves specific user problems without overwhelming the interface with unnecessary options.

During the vetting process, designers review every user journey—from initial launch to complex operations. If a workflow feels redundant or cluttered, the team works with the developer to refine, relocate, or remove features that distract from the application's primary function.

Active Collaboration and Design Iteration

The vetting process is rarely a simple pass-or-fail evaluation. Instead, it is an active, iterative collaboration:

  1. Design Issues and Mockups: Designers frequently create official mockups using GNOME’s design libraries to demonstrate how an interface should look and behave.
  2. Usability Feedback: The team identifies edge cases, confusing terminology, and potential friction points in the interface before the app enters the release cycle.
  3. Refactoring Roadmaps: If an app shows potential but falls short of core criteria, the Design Team outlines a specific design roadmap that developers must complete before reconsideration.

Accessibility and System Integration

A core application must be accessible to all users. The Design Team verifies that interfaces accommodate high-contrast modes, dynamic text scaling, and proper keyboard navigation. They also ensure the application integrates smoothly with core system services, such as native file pickers, notifications, and dark/light color scheme switching.

Recommendation to the Release Team

While the GNOME Release Team makes the final bureaucratic decision on software inclusion, the Design Team holds functional veto power regarding user experience. An application cannot become a GNOME Core component without explicit approval from the Design Team, ensuring that GNOME delivers a unified, polished, and intuitive desktop environment.
