How to Manage GNOME Per-Application Volume Settings

This article provides a direct overview of how the GNOME desktop environment handles per-application volume controls within its native sound settings panel. It covers the dynamic detection of active audio streams, the role of modern sound servers like PipeWire and PulseAudio, and how users can manage and persist independent volume levels for individual programs without third-party software.

The Underlying Audio Architecture

GNOME does not manage audio streams directly; instead, it interfaces with the system's sound server—most commonly PipeWire (managed by WirePlumber) on modern distributions, or PulseAudio on older releases.

When an application plays audio, it opens a stream with the sound server. The GNOME Control Center (gnome-control-center) queries these streams using standard desktop audio APIs via D-Bus. This architecture allows GNOME to expose individual stream properties—such as the application name, current volume, and mute status—directly to the graphical user interface.

Dynamic Stream Detection

In the GNOME Settings application under the Sound panel, per-application controls are located in the Volume Levels section. This panel is fully dynamic:

  • Active Streams Only: Applications only appear in the list when they are actively playing audio or holding an open output stream. If an application is idle or closed, it will not appear in the Volume Levels list.
  • Instant Population: As soon as an application begins playback (such as a web browser starting a video), GNOME detects the stream and instantly renders an entry for it.
  • Stream Removal: When an application terminates its audio session, its entry automatically disappears from the panel.

Controls and Independent Levels

Each detected application in the panel receives its own dedicated interface element, providing two primary controls:

  1. Volume Slider: Adjusts the application's output relative to the master system volume. Lowering an app's slider attenuates its sound without lowering the system-wide master output.
  2. Mute Toggle: Completely silences the selected application without affecting other active streams or the master volume.

GNOME respects relative volume scaling. If the system master volume is adjusted, individual application outputs scale proportionally based on their specific levels.

Volume Persistence

Changes made within the Volume Levels section are persistent. PipeWire and PulseAudio track client properties—such as the executable binary name (application.process.binary) or the desktop entry ID (application.id).

When you set an application’s volume to 50% and close it, the sound server stores that preference in its state database. The next time the application opens and starts an audio stream, the sound server restores the previously assigned volume level, which is immediately reflected in GNOME's sound settings panel.
