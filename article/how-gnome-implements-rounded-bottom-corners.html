How GNOME Implements Rounded Bottom Corners

This article explains the technical mechanism behind how the modern GNOME desktop environment renders rounded bottom corners on native application windows. Historically restricted to square edges, native bottom-corner rounding is achieved through the transition to GTK4 and Libadwaita, utilizing Client-Side Decorations (CSD), GTK Scene Kit (GSK) clip nodes, and transparent buffer regions coordinated with the Mutter compositor.

Client-Side Decorations (CSD)

In traditional desktop environments, the window manager draws the outer frame and title bar. GNOME uses Client-Side Decorations (CSD), meaning the application itself is responsible for rendering its entire frame, including header bars, borders, shadows, and corners.

Because the application controls the entire window surface, it is not bound by rigid window-manager constraints. Instead, the application passes a fully rendered graphical buffer—already shaped and stylized—directly to GNOME’s compositor, Mutter, via the Wayland protocol (or X11).

Libadwaita and CSS Theming

The visual standardization of rounded bottom corners arrived with GNOME 42 and the introduction of Libadwaita, the styling library built on top of GTK4.

In older GTK3 applications, bottom corners were typically kept sharp to simplify resizing operations and prevent rendering artifacts. Libadwaita standardized the window geometry by applying CSS border-radius rules to top-level window containers (AdwApplicationWindow or AdwWindow). The application style sheet defines a border radius on both the top and bottom corners of the primary window widget, instructing the rendering engine to curve all four extremities uniformly.

GTK Scene Kit (GSK) and Clip Nodes

Applying a border-radius in a GUI toolkit requires that child widgets (such as text views, sidebars, or status bars) do not bleed over the rounded edge. GTK4 solves this through the GTK Scene Kit (GSK).

GSK represents the interface as a tree of render nodes passed to a rendering backend (such as Vulkan or OpenGL). To create rounded corners:

  1. Clip Node Creation: GSK creates a GskRoundedClipNode encompassing the window boundary.
  2. GPU-Accelerated Clipping: The GPU shader tests pixels against the mathematical bounds of the rounded rectangle.
  3. Anti-Aliased Edges: The fragment shader computes smooth, anti-aliased edges along the curve, ensuring that underlying child components are clipped without jagged borders.

Buffer Padding, Shadows, and Input Regions

A window with rounded corners requires transparent space in the corners so that the underlying desktop or other windows remain visible through the curved edges.

  • Subsurfaces and Alpha Channels: The client allocates a buffer that includes the window content plus an extended transparent perimeter for the drop shadow. The corners are simply pixels with an alpha value of zero.
  • Input Shape Regions: Because the buffer rectangle is strictly rectangular, the application must define an input region using Wayland protocols (wl_surface.set_input_region). This ensures that mouse clicks in the transparent pixels just outside the rounded corner pass through to whatever window is beneath it, rather than being captured by the foreground application.
