How GNOME Manages Time Sync Using systemd-timesyncd

GNOME manages system time synchronization through a layered architecture that connects user settings to low-level system services using D-Bus. Rather than directly controlling the background synchronization service, GNOME interfaces with systemd-timedated, an intermediary system bus mechanism that safely coordinates configuration changes with the lightweight NTP client systemd-timesyncd. This setup ensures accurate timekeeping while maintaining strict privilege separation and desktop-agnostic system standards.

The Component Stack

The integration relies on three primary software layers:

  1. GNOME Control Center (GNOME Settings): The graphical user interface where users view and toggle the "Automatic Date & Time" setting.
  2. systemd-timedated: A privileged system daemon exposing the org.freedesktop.timedate1 D-Bus interface, responsible for handling date, time, and NTP configuration requests.
  3. systemd-timesyncd: The background daemon that acts as an SNTP (Simple Network Time Protocol) client, querying remote NTP servers and adjusting the local system clock.

D-Bus Communication via systemd-timedated

GNOME does not execute shell commands or directly manipulate systemd units to configure time synchronization. When a user toggles "Automatic Date & Time" in the GNOME Settings panel:

  1. GNOME Settings communicates with timedated over the system D-Bus.
  2. It invokes the SetNTP(boolean use_ntp, boolean interactive) method on the org.freedesktop.timedate1 interface.
  3. PolicyKit (polkit) evaluates whether the calling user has administrative privileges to alter system-wide time configurations. In standard desktop installations, active local users are granted permission automatically.

Controlling systemd-timesyncd

Once systemd-timedated accepts the request to enable NTP:

  • It enables and starts the systemd-timesyncd.service systemd unit.
  • Conversely, if the user disables automatic time synchronization, systemd-timedated stops and disables the unit, allowing manual setting of the time via the SetTime D-Bus method.
  • timedated dynamically detects the available NTP implementation. If a full-featured NTP daemon such as Chrony or NTPd is installed and active, timedated defers control to that service instead of systemd-timesyncd.

Clock Synchronization and Network Handling

When active, systemd-timesyncd synchronizes the system clock by querying NTP servers defined in /etc/systemd/timesyncd.conf or dynamically provided via DHCP by network managers like NetworkManager.

As NetworkManager establishes or alters network interfaces, it can feed runtime NTP server data to systemd-timesyncd. The daemon gradually steps or slews the system clock using the Linux kernel's time adjustment APIs (such as adjtimex). It also periodically writes the current time to a local state file (/var/lib/systemd/timesync/clock) to prevent time from jumping backward across system reboots on hardware lacking a reliable Real-Time Clock (RTC).
