How GNOME Supports Variable Refresh Rates

Variable Refresh Rate (VRR) support in GNOME allows compatible monitors to synchronize their refresh rates with the frame rate of applications, drastically reducing screen tearing and motion stutter during gaming and video playback. Implemented directly within GNOME’s Wayland compositor, Mutter, VRR provides a smoother visual experience on hardware that supports AMD FreeSync or NVIDIA G-Sync. This article details the underlying architecture of GNOME's VRR implementation, current compatibility status, and the configuration steps required to activate the feature.

The Architecture Behind GNOME’s VRR

GNOME’s VRR capability is handled within Mutter, the window and compositing manager for GNOME. Historically, compositors ran at a fixed refresh rate dictated by the display’s maximum or selected frequency (e.g., 60Hz or 144Hz). If a 3D application or game produced 75 frames per second on a 144Hz monitor, the mismatch resulted in judder or frame duplication.

Under GNOME’s Wayland session, Mutter implements VRR by dynamically adjusting the presentation timing of monitor scanouts based on when the client application finishes rendering a frame. When a supported application enters fullscreen or presents new frames, Mutter requests the kernel’s Direct Rendering Manager (DRM) to present the frame immediately within the monitor's supported refresh rate window, rather than waiting for the next fixed vertical blanking interval (VBLANK).

Hardware and Driver Requirements

To utilize VRR on GNOME, specific hardware and software prerequisites must be met:

  • Display: A monitor supporting AMD FreeSync, NVIDIA G-Sync Compatible, or VESA Adaptive-Sync over DisplayPort or HDMI 2.1.
  • GPU & Drivers:
    • AMD Radeon GPUs using the open-source amdgpu driver.
    • Intel integrated and discrete graphics using the i915 or xe drivers.
    • NVIDIA GPUs using modern proprietary drivers (555 series or newer) that support Wayland explicit sync and variable presentation modes.
  • Display Server: Wayland is required. The legacy X11 session does not support GNOME's native per-monitor VRR implementation.

Enabling VRR in GNOME

While full out-of-the-box automation is targeted for future standard releases, GNOME 46 and GNOME 47 include VRR as an experimental feature.

To enable the setting, users must add variable-refresh-rate to Mutter's experimental features via the terminal:

gsettings set org.gnome.mutter experimental-features "['variable-refresh-rate']"

Once the experimental flag is active:

  1. Open Settings.
  2. Navigate to the Displays section.
  3. Select the target monitor.
  4. Locate the Variable Refresh Rate toggle switch and turn it on.

Application Behavior and Desktop Compositing

When enabled, Mutter dynamically evaluates active surfaces:

  • Fullscreen Applications: Games or 3D applications running in exclusive fullscreen mode directly drive the display’s refresh rate between the monitor's minimum and maximum frequency limits (e.g., 48Hz to 165Hz).
  • Desktop and Windowed Modes: To avoid flickering or erratic refresh behavior caused by low-activity desktop elements, Mutter keeps the display at its highest native refresh rate when standard desktop windows are in focus, engaging dynamic timing primarily when high-frame-rate, single-surface content demands it.
