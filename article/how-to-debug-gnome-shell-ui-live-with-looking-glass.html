How to Debug GNOME Shell UI Live With Looking Glass

GNOME Shell’s Looking Glass tool serves as an integrated, interactive debugging console and graphical inspector specifically designed for the GNOME desktop environment. It allows extension developers and system tweakers to inspect visual UI elements, evaluate JavaScript code in real time, view error logs, and manipulate the visual state of the desktop without restarting the shell. This guide explores the core functions of Looking Glass and how to leverage it to debug and modify GNOME Shell user interface components on the fly.

Launching Looking Glass

Looking Glass is embedded directly into the GNOME Shell runtime on X11 and native Wayland sessions. To launch the tool:

  1. Press Alt + F2 to open the "Run a Command" prompt.
  2. Type lg and press Enter.

The Looking Glass interface drops down from the top of the screen, providing an interactive overlay divided into tabs: Evaluator, Windows, Errors, Memory, and Extensions.

Interactive Element Picker

The primary function for live UI debugging is the element picker tool, represented by the "Picker" button in the top-left corner of the Looking Glass overlay.

  • Selection: Clicking the Picker button enables an interactive selection mode. Hovering over any element on the desktop (such as panels, app indicators, notifications, or dock icons) highlights the underlying Clutter or St (Shell Toolkit) actor.
  • Actor Inspection: Clicking an element selects it and closes the picker, outputting the element’s reference into the evaluator window.
  • Hierarchy Traversal: Once an element is selected, Looking Glass displays its object type (e.g., St.BoxLayout, St.Button, or Clutter.Actor), its hierarchy, dimensions, position, and applied CSS pseudo-classes.

Live Manipulation and JavaScript Evaluation

Looking Glass runs an integrated SpiderMonkey JavaScript interpreter directly within the GNOME Shell process. This allows developers to modify the live user interface dynamically.

  • The $r Variable: When you inspect an element with the Picker, Looking Glass automatically binds that object to the special result variable $r.
  • Modifying Properties: You can alter the properties of the selected element immediately. For example, entering $r.hide() removes the element from the display, while $r.set_width(300) resizes it.
  • Modifying Styles: You can test CSS modifications on the fly by executing methods like $r.set_style('background-color: red; color: white;'). This allows for immediate visual feedback before hardcoding styles into a custom theme or extension stylesheet.

Real-Time Error Logging

The Errors tab tracks runtime exceptions, warnings, and messages generated by the shell and active extensions.

  • Tracebacks: When a UI component fails to render or an extension crashes, Looking Glass logs the complete JavaScript stack trace.
  • Live Logging: Developers can insert console.log() or log() statements in their extension code and view the output directly in the Errors tab without needing to monitor journalctl in an external terminal window.

Managing Extensions and Memory

Beyond direct UI manipulation, Looking Glass provides system-level debugging tools:

  • Extensions Tab: Lists all installed extensions, their states, and links to their source directories. Developers can quickly view which extensions are active or throwing errors.
  • Memory Tab: Helps diagnose memory leaks caused by lingering Clutter actors. When building custom UI components, Looking Glass can verify whether discarded elements are properly destroyed or still occupying system memory.

To exit Looking Glass at any time, press the Escape key.
