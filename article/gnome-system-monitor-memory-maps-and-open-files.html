GNOME System Monitor Memory Maps and Open Files

GNOME System Monitor provides detailed insights into active system processes, including the ability to inspect process memory maps and track open files in real time. This capability stems from the tool's integration with Linux kernel interfaces, backend data extraction libraries, and dedicated graphical inspection utilities. Together, these features allow users, system administrators, and developers to debug memory usage, detect memory leaks, and identify locked files without relying solely on command-line utilities.

Linux /proc Filesystem Integration

The primary feature enabling GNOME System Monitor to inspect internal process states is its deep integration with the Linux /proc virtual filesystem:

  • Memory Maps Parsing: For any given process ID (PID), the Linux kernel exposes memory layout information through /proc/[pid]/maps and /proc/[pid]/smaps. GNOME System Monitor reads these files to display the virtual address space, permissions (read, write, execute, shared), offset, device numbers, inode, and the file backing the mapping (such as shared dynamic libraries, executable code, the heap, or the stack).
  • Open File Descriptors Tracking: The kernel tracks open files under /proc/[pid]/fd/, where each file descriptor is represented as a symbolic link pointing to the actual resource. GNOME System Monitor resolves these links to show open regular files, UNIX domain sockets, network connections, pipes, and character devices held by the target process.

Abstraction via the libgtop Library

GNOME System Monitor does not manually parse every kernel file from scratch. Instead, it relies on libgtop, a dedicated GNOME library designed for system monitoring.

libgtop abstracts kernel-level system calls and low-level data structures into standardized C/C++ APIs. It provides built-in functions specifically tailored to extract:

  • Process memory parameters (clean/dirty memory pages, shared versus private memory).
  • File descriptor tables and socket references.

By utilizing libgtop, GNOME System Monitor ensures low CPU overhead and high performance when fetching memory segments and file lists for processes containing thousands of open handles or mapped regions.

Dedicated GUI Inspection Windows

To translate raw kernel data into an actionable format, GNOME System Monitor includes dedicated contextual dialogs:

  • Memory Maps Dialog: Accessible by right-clicking a process and selecting "Memory Maps." This interface organizes memory segments in a readable table showing start and end addresses, virtual memory flags, virtual size, resident set size (RSS), shared memory, and file associations. It also includes an integrated search filter to quickly find specific mapped libraries or address ranges.
  • Open Files Dialog: Accessible via the "Open Files" option in the process context menu. It aggregates and displays all file descriptors held by the process, categorizing them by descriptor number and object path. A built-in search tool allows users to locate specific file paths or check if a process is preventing a storage volume from being unmounted.

System Permissions and Access Control

GNOME System Monitor respects Linux Discretionary Access Control (DAC) and kernel security models (such as Yama ptrace protections). When executed by a standard user, it reads the memory maps and file descriptors of processes owned by that user. When elevated permissions are provided or when run as root, it can query privileged system services, kernel threads, and processes owned by other users across the system.
