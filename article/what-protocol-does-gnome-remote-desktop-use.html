What Protocol Does GNOME Remote Desktop Use?

GNOME Remote Desktop primarily uses the Remote Desktop Protocol (RDP) to support native screen sharing and remote system control. While earlier iterations of the GNOME desktop relied on Virtual Network Computing (VNC), modern GNOME environments have shifted to RDP as the default standard. This architecture pairs RDP with native Linux multimedia subsystems like PipeWire to deliver performant, encrypted, and feature-rich remote desktop sessions on modern Wayland displays.

The Shift to RDP

Beginning primarily with GNOME 42, the desktop environment adopted Microsoft’s Remote Desktop Protocol (RDP) as its primary backend. RDP offers several performance and usability advantages over older protocols, including lower latency, native encryption via TLS, and reduced bandwidth consumption.

Through RDP, GNOME Remote Desktop supports:

  • Hardware-accelerated screen capture and video encoding.
  • Bidirectional clipboard sharing (text and images).
  • Dynamic screen resizing to match the client window.
  • Native remote audio streaming.

Legacy Support for VNC

GNOME Remote Desktop retains optional, legacy support for Virtual Network Computing (VNC) via the RFB (Remote Framebuffer) protocol. However, VNC is largely treated as secondary. It lacks the modern performance optimizations, integrated audio redirection, and seamless authentication mechanisms provided by the RDP implementation. Consequently, standard system settings in modern distributions (such as Fedora and Ubuntu) configure RDP by default when remote desktop sharing is toggled on.

Underlying Display Pipeline: Wayland and PipeWire

The RDP implementation in GNOME does not capture the screen directly through low-level display hooks. Instead, it relies on modern Linux desktop plumbing to ensure security and sandboxing:

  1. PipeWire: Captures the video stream directly from the compositor (Mutter) securely.
  2. libei / Mutter: Handles remote input emulation (keyboard and mouse events) safely without compromising Wayland's security model.
  3. GNOME Remote Desktop Daemon: Bridges the input and output streams, encodes the video, and communicates with the client machine using the RDP specification.

This integrated approach allows GNOME Remote Desktop to support both desktop sharing (mirroring an existing session) and headless remote logins (creating a dedicated virtual session) natively via RDP.
